Project 05 · Applied LLMs

Small scope, all the way to deployed.

A note-taking app with semantic search across notes. The point was never the feature list — it was getting something the whole distance to a working deployment.

Why deliberately small.

There's a long distance between a notebook that works and a thing someone can use, and most of the interesting problems live in that gap. Notely was scoped small specifically so that gap was the whole project.

Notes go in, get embedded, and become searchable by meaning rather than keyword — so "that thing about retrieval latency" finds the note even when those words never appear in it. The LLM handles summarisation over retrieved notes.

  • Embedding on write — notes are embedded when saved, not at query time, so search stays fast as the collection grows.
  • Semantic retrieval — nearest-neighbour lookup over the note embeddings, which is exactly where dense retrieval is the right tool: short, paraphrase-heavy, personal text.
  • LLM summarisation — synthesis over retrieved notes rather than over everything, which keeps context windows and cost bounded.
  • Deployed and used — Streamlit, running, not a screenshot in a README.
The honest framing

This is the project where dense-only retrieval is genuinely the right call. Knowing when the simple approach suffices is the same skill as knowing when it doesn't.
